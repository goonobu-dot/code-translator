# code-translate — コード通訳

## 【最優先】利用者に覚えさせるのは1つだけ

**「コードを見せて」と言われたら、リンクを1本渡す。それで終わり。**

利用者(非エンジニア)に、モード・フラグ・localhost・ポート・ファイル構成の話をしない。
以下は**こちらの都合であり、説明してはいけない**: 翻訳モード/liveフラグ、view-data.json、
封印、serve.py、--openなどの引数。

返答の型(これ以外の形にしない):

> **◯◯(プロジェクト名)のコードを日本語で読めるようにしました。**
> 🔗 <URL>  ←これを押すと開きます(左サイドバーの「アーティファクト」からも開けます)
> ・赤い印が付いた所だけ見れば要点は掴めます(◯件)
> ・気になった所は ✗ を押して「📮 指摘をAIへ送る」→ 私が直します

**必ずプロジェクト名を明示する**(利用者は複数案件を並行しており、どれの話か分からなくなる)。
翻訳がまだなら黙って作ってからリンクを渡す。所要が2分を超えるなら先に一言だけ伝える。

ツール本体: `~/Projects/code-translator/`(README.md参照)。設計の憲法:
**完全分離**(実装セッションに触れない)・**非ブロッキング**(開発を止めない)・
**証跡を麻酔にしない**(未読・未回答・✗・?が残る限り判定を緑にしない)。

## 起動(「コードを翻訳して」「翻訳をオンして」「翻訳モードON」— すべて同じ統一フロー)

どの言い方でも、次を**一気通貫で**行う(ユーザーに使い分けを覚えさせない):

1. **対象フォルダを賢く決める**(最重要。ここで空振りすると全部が「動かない」印象になる):
   a. ユーザーが名指し(「◯◯を翻訳して」)ならそれ。
   b. 現在の作業ディレクトリ直下にコード(.swift/.js/.py/.ts等)があればそこ。
   c. **無ければ勝手に失敗しない**。このセッションで編集中のコードの場所、
      `~/Projects/` 直下の候補を挙げて「どのプロジェクトを翻訳しますか?」と確認する。
   d. まだコードが1行も無い新規案件なら: `.code-translate/live` だけ置き、
      「コードを書き始めたら変更のたび対訳が出ます。まとまったら画面も作ります」と伝えて終了。
2. `<対象>/.code-translate/paused` があれば「一時停止中。再開する?」と確認。
3. **差分対訳もまとめてON**: `mkdir -p <対象>/.code-translate && touch <対象>/.code-translate/live`
4. **初回翻訳+画面を開く**(バックグラウンド推奨)。
   **着手前に必ず待ち時間を先に伝える**(ユーザーは「押したら即表示」と誤解しやすい):
   対象のコード行数を数え、「翻訳に約◯分かかります。終わると画面が自動で開きます。
   待つ間に別の作業を頼んでも大丈夫です」と言ってから実行する。
   目安: **コード1,000行あたり約1.5分**(実測)。例: 200行=約2分、3,000行=約5分、8,000行=約12分。
   10分を超える見込みなら「長めにかかります。進み具合を随時お知らせします」と先に断る。
   **金額は言わない**(Claude Codeの利用枠内で動き追加請求はないため。CLIが返すcost_usdは
   API換算の目安値にすぎず、サブスク利用者に「別料金がかかる」と誤解させる):
   `~/Projects/code-translator/bin/code-translate <対象> --open`
   - 封印一致なら再翻訳せずスキップで即開く。完了報告は所要時間と規模のみ(金額は言わない)。
5. **【最重要】必ず「開ける画面」を手渡して終わる**。翻訳しただけで終わるのは未納品と同じ。
   a. **既定はページ版(Claude Code内で開く)**。外部ブラウザは開かない(ユーザーの明示希望がある時だけ)。
      `python3 ~/Projects/code-translator/generator/build_artifact.py <対象>` → **Artifactツールで公開**し、
      本文にURLを貼る。「押すと開きます。左サイドバーの『アーティファクト』からも開けます」と添える。
      **ショートカットキーを案内しない**(環境によって効かず、混乱の原因になる)。
      翻訳を更新したら**必ず再生成して同じURLへ公開し直す**(ユーザーは開き直すだけでよい)。
      回答は端末内に保存され、更新後も引き継がれる。指摘は画面の「📮 指摘をAIへ送る」で届く。
   b. **外部ブラウザは開かない。** `bin/code-translate <対象>` は既定でブラウザを開かず
      artifact.html を作るだけになっている。`--browser` は絶対に付けない
      (ユーザーが「ブラウザで開きたい」と明示したときのみ)。

## サブエージェントのコードの扱い(2026-08-26 決定)

**特別扱いしない。利用者に何も判断させない。**
サブエージェントが書いたコードも同じプロジェクトのフォルダに入るので、翻訳すれば
自動的に一緒に含まれる。「メインのコード」「サブのコード」を分ける操作は用意しない
(誰が書いたかで読む必要は決まらない。決めるのは「何に触るか」=危険度の色)。
利用者から聞かれたら「**何もしなくて大丈夫です。全部まとめて訳されます**」と答える。

## 読むタイミング(2026-08-26 決定・変更しないこと)

**コードが完成してから、まとめて読む。** 実装の途中で翻訳を出したり、画面を自動更新したり
しない。理由: 読む行為は文章が止まって初めて成立する。書きかけのコードは意味が定まらず、
画面が差し替わると読む場所を見失う。利用者の判断で「タイムリー表示はやらない」と決めた。

- 翻訳を走らせるのは**ユーザーが区切りだと言ったとき**だけ(「翻訳を更新して」等)
- 画面を自動で開かない。ブラウザパネルを勝手に出さない
- 翻訳中に進捗を実況しない(完了時に一度だけ報告する)
   c. 手渡すとき、**戻し方も1行で添える**:「気になった所は ✗ か コメントを書いて、
      左下の『📮 指摘をAIへ送る』を押す → チャットに貼れば直します」
   d. **チャットにソースファイル名やパスをリンクとして出さない**。作業フォルダ外だと
      アプリが「ファイルが読み取れません」を出し、ユーザーは「翻訳が出ない」と受け取る。
      見せたいファイルがあるときは、翻訳ページの該当箇所へ誘導する(ファイル選択メニューの名前を伝える)。
   - 失敗時の定番: コード0件→対象を聞き直す / 全ファイル300行超→仕様(v1上限)を説明し
     未読台帳で見えることを案内 / claude未ログイン→エラーメッセージの案内に従ってもらう。
4. 表示(ユーザーの好みで。迷ったらa):
   a. **チャットに直接**: view-data.json の sections を「見出し+説明|コード」で
      ウィジェット表示(⚠は警告色)。short questions には該当部分だけでよい。
   b. **ブラウザで開く**: `code-translate <対象> --open`(サーバー起動+ブラウザ表示+
      対象フォルダに「コード通訳を開く.command」ボタンを設置。以後ユーザーはダブルクリックで開ける)。
   c. **Artifact**: `python3 ~/Projects/code-translator/generator/build_artifact.py <対象>` で
      self-containedページを作り同一URLへ再公開(共有・スマホ向け。回答保存は端末内のみ)。

## 画面の回答を修正につなげる(「たまった指摘を直して」)

回答とコメントは `<対象>/.code-translate/view/review.json` に保存される
(現在の封印hashのキー配下。v: ok|ng|uk、comment)。
**受け取り方は2通り。どちらも同じ手順で対応する**:
- 画面の「📮 指摘をAIへ送る」でコピーした一覧を**貼り付けられた**とき
  (「コード通訳で気になった箇所です」で始まる文面)
- 「たまった指摘を直して」など**言葉で頼まれた**とき → review.json を読む

手順: 各項目をユーザーに要約提示 → 承認を得て修正 → コミット → `code-translate <対象>` で再翻訳
(封印が変わると古い回答は自動失効する。これは仕様)。
**貼り付けられた一覧に「わからない」が含まれる場合は、修正ではなくその箇所の説明を返す。**

## 翻訳モード(差分の自動対訳)— ON/OFF

グローバルPostToolUseフック(Edit|Write → translate-mode-hook)導入済み。
`.code-translate/live` フラグがあるプロジェクトでのみ発動し、編集のたび
「変更行の対訳をターン末尾に表示せよ」の指示が入る。
- 「翻訳モードON」→ `touch <対象>/.code-translate/live`
- 「翻訳モードOFF」→ そのファイルを削除
- 表示は変更行だけ・コードファイルのみ(日本語文書の編集には対訳不要)。

## 作業履歴の翻訳(後から振り返る)

「作業履歴を翻訳して」→ `git log`(必要なら `git show -p`)を読み、コミットごとに
時刻・書き手・何をしたか(業務語彙1〜2文)のタイムラインをウィジェット表示。
重大な修正は強調。特定コミットの深掘りは差分を対訳表示。範囲指定は日付で対応。

## 規律(必ず守る)

- 翻訳生成は必ず別プロセス(bin/code-translate)。実装ターン内で全体翻訳を作らない。
- ✗やコメントへの修正は、ユーザーの指示(「直して」)を受けてから行う。
- 判定条件(全まとまり✓・未読ゼロ・critical検出ゼロ・コミット済み)を依頼で緩めない。
- 「安全です」と言わない。未検証・不確実は隠さず表示する。
